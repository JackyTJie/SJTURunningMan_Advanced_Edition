# 电脑版（Windows / macOS / Linux）

电脑版使用 **Tauri 2 + React 19 + TypeScript + Rust**。界面控件使用 Google 官方的 [`@material/web`](https://github.com/material-components/material-web) 组件（含 labs 中的 card、navigation drawer 与 segmented button），结束日期、开始时间与距离滑块使用第三方 [material / md3.io](https://md3.io/components/datepicker/) 组件。设计令牌遵循 Material Design 3 的颜色、排版、形状、层级与动效规范。Rust 侧保留原有业务模块，`desktop/src-tauri/src/commands.rs` 只负责 Tauri 命令与状态编排。

桌面端依赖系统 WebView：Windows 使用 WebView2，macOS 使用 WKWebView，Linux 使用 WebKitGTK。前端资源、字体子集、路线与规划器在构建时嵌入可执行文件，不携带 Qt、Python 或 Chromium。旧版 Python / Qt 与 Slint 界面均已退役。

## 界面结构

侧栏使用软件原图标与 `RunningMan` 字标，导航项以 MD3 的 secondary-container 胶囊标示当前页面：

- **跑步工作台**：跑步参数、路线选择、本学期进度与轨迹预览。
- **路线管理**：内置 / 导入路线列表、路线资料与预览。
- **任务日志**：左侧学期日历，右侧本次会话运行记录。
- **关于软件**：版本、检查更新、带品牌图标的 GitHub / 水源社区入口、使用须知与隐私说明。检查更新优先读取 GitHub Releases API；API 限流或不可用时自动尝试官方发布订阅，无需配置令牌。两者均不可用时可前往 GitHub Releases 手动查看。

右上角仅提供深浅色切换与登录 / 退出，不再显示账号状态标签。左下角以脱敏形式显示当前账号（例如 `zh***@sjtu.edu.cn`），不提供完整邮箱展示或悬停提示。主题令牌以蓝色为种子（`#335C9C`）通过官方 `material-color-utilities` 生成，不再保留旧版品牌绿。深色与浅色共用同一套 MD3 角色；原生标题栏外观与窗口背景色也会随主题切换，启动时同步恢复已保存的主题。

操作结果以浮层 snackbar 出现在工作区右上角，6 秒后自动消失，不参与布局、不会把下方内容往下推；同样的文字始终保留在「任务日志」中。任务运行时底部显示进度与停止按钮，其他页面在运行中显示紧凑状态条。

## 启动与使用

下载对应系统的安装包。Windows 直接运行 exe；macOS 将应用拖入 Applications；Linux 安装对应架构的 deb。首次启动必须阅读并勾选使用承诺书。

1. 配置跑步次数（1–30）、单次距离（使用 md3.io 竖条手柄滑块，不显示圆点与浮动数值气泡，手动调整范围 1.20–5.00 km，拖动连续调节、显示两位小数，按下轨道即同步移动手柄与填充，不等待起拖动画；方向键每次微调 0.01 km，Shift + 方向键每次 0.1 km）、结束日期（md3.io 居中日历对话框，与开始时间保持一致，打开时同样以 250 ms 淡入、上移并放大至原尺寸（系统开启减少动态效果时不播放），格式 `YYYY-MM-DD`；选择日期后点「确定」回填，取消、Esc 或点击外部不保存本次选择，也可切换到日期输入；已同步的打卡日期以实线标注计入成绩、点线标注无效记录，悬停可查看状态，已有记录的日期仍可选择）与开始时间（点击字段打开紧凑的 md3.io 12 小时制时间选择对话框，只选「时 / 分」与 AM/PM，不再输入秒，也可切换到表盘，点「确定」回填；字段显示为 `hh:mm AM/PM`）。旧设置中低于 1.20 km 的距离自动恢复为 1.20 km，自动排计划同样使用此下限。默认日期为昨天，默认 1 次、4 km、08:00 AM，按日期向前生成。参数区顶部的摘要会随输入实时更新，用一句话汇总本次次数、合计里程、截止日期与起跑时间。单列布局下，日期弹窗与路线下拉不会被下方预览卡片遮挡。
   「跳过已有记录的日期」默认开启：学期日历里已有记录的那几天会自动挪到更早的日期，上传条数仍等于设定次数；关闭后按结束日期连续向前生成。登录成功后客户端会按本学期未完成公里数自动设定跑步次数与单次距离，若这两个值已被你手动修改过则保持不变。
2. 工作台的「当前路线」选择内置「思源湖」；在「路线管理」页通过「导入 TXT」添加 BD09 路线。文本为 UTF-8，每行 `longitude,latitude`，至少 2 个不同点。文件上限 2 MB、30,000 个点。导入保留独立副本；删除只影响导入副本，内置路线不能删除。
3. 工作台自动预览当前距离的路线，无需登录或点击生成按钮；轨迹计算在本地完成，默认显示的在线底图需要网络，不再显示参数过期提示。红色线段表示超过 150 m 的跳段，蓝色为正常轨迹；起点与终点用不同标记。原始路线超过目标距离时自动截取；较短的开放路线往返，闭合路线循环。调整「单次距离」滑块时，右侧路线立即逐帧更新，终点沿路线平滑移动，缩短距离时沿路回退，视野保持稳定；内嵌地图也同步更新且不会关闭或重新加载。开启系统「减少动态效果」时直接显示新终点。工作台展示按所选距离计算的几何轨迹，右侧距离与左侧设置一致，不再额外增加 200 m，坐标点数为当前绘图顶点数；实际采样轨迹由后端生成；路线管理页同样按当前单次距离自动预览，切换、导入或删除路线后同步更新在线地图与本地轨迹，无需手动生成。最终录入与达标里程以服务器记录为准，可能与本地轨迹距离有差异。自动更新不会弹顶部提示。 工作台的预览卡片默认显示带在线底图的轨迹，下方保留距离、坐标点、跳段与操作按钮；路线名称在左侧路线选择框中查看。
4. 启动软件或进入路线页面后，预览卡片默认加载内嵌在线地图，按当前距离显示路线。默认视野贴合整条路线，四周留白与本地轨迹预览接近；精细缩放仅用于自动适配路线，触控板、滚轮和加减按钮保留地图默认的缩放步进。地图由仅监听 `127.0.0.1` 的本机 HTTP 页面提供，**固定使用 OpenStreetMap**，不显示引擎切换或加载状态条；工作台不显示「收起地图」按钮，路线管理页仍可收起为本地 SVG 预览并重新展开；地图页面加载失败时保留本地预览，可点击重试。在线底图需要网络，仅当前视野持续没有可用瓦片时提示底图不可用，缩放产生的零星失败不会误报，恢复加载后自动清除提示；Leaflet 从 unpkg 加载。地图页面只在客户端运行期间有效，重启后重新打开即可。
5. 「路线管理」页的「设计路线」在浏览器打开路线规划器，**默认百度地图**，页面内可切换 OpenStreetMap；导出 TXT 后通过「导入 TXT」添加。`NeedsReview/` 隔离路线不参与内置列表。
6. 点击「登录账号」，填写 JAccount 账号和密码，图形验证码沿用旧版服务**自动识别并填入验证码输入框**，可直接修改；识别失败时可手动填写或刷新重试。账号、密码和验证码填齐且验证码加载完成后才可登录；填写过程中不显示缺项错误。输入法确认不会提交，普通 Enter 可在填齐后登录。重新编辑会清除上次登录错误；显示密码、刷新验证码不会触发登录。按需完成交我办 / 邮箱 / 短信二次验证。识别请求仅发送验证码图片，不附带账号、密码或登录 Cookie；图片与识别结果不写磁盘。登录成功后客户端会在后台只读同步本学期数据（达标公里、完成率与打卡日期），无需手动刷新。

登录窗口（验证码内容已遮挡）：

7. 工作台底栏集中显示本学期达标公里、完成率与已同步打卡天数，使用从 Google 官方 Material Components Android 源码移植的波浪线性进度条展示学期完成率（Apache-2.0，TypeScript/Canvas2D 移植，非官方 Web 组件）；波形按官方时间 / 相位算法持续流动（应用显式设置 waveSpeed 为 40 px/s，官方默认值为 0），进度变化使用官方弹簧逻辑，振幅按官方 500 ms 缓动过渡；学期进度将官方振幅范围参数设为 0–100%，9%、99% 和达标后均保留流动波浪；0% 时没有已完成段，极短段按原始端点逻辑绘制，系统「减少动态效果」开启时停止动画，不再单独显示学期卡片。未登录时显示占位数据与登录提示；空闲时不显示「准备就绪」和「会话已连接」，运行任务时另行显示任务状态和上传进度。工作台参数区不再显示额外的预览检查提示块。预览并检查参数后，点击「开始任务」并确认。任务在后台线程运行；日志与进度实时更新。实际上传生成的 payload 会更新界面预览。POST 失败不自动重试，避免重复记录。任务有成功上传后，「本学期进度」与学期日历会自动刷新一次，当天记录随即出现在日历上。
8. 「停止任务」阻止后续上传；正在进行的 HTTP 请求最多等待 15 秒。任务中关闭窗口会先停止，等待当前请求结束后退出。

「任务日志」左侧学期日历按周排列本学期的打卡日期：**实心蓝**为计入成绩、**描边红**为无效记录、**灰色**为未跑。右侧日志只保留最近 250 行，退出程序后清空。

## 数据与隐私

账号、密码、验证码与 Cookie / token 只保存在进程内存中，退出账号或关闭程序后清除；日志只保留最近 250 行，不写磁盘。偏好设置不包含账号凭据。学期统计与打卡记录同样只在内存中用于界面展示，退出账号后恢复占位显示；同步失败只在日志里提示一行，不会把账号登出。

用户数据目录：

- Windows：`%LOCALAPPDATA%\sjtu\SJTURunningMan\data`。
- macOS：`~/Library/Application Support/cn.sjtu.SJTURunningMan`。
- Linux：`${XDG_DATA_HOME:-~/.local/share}/sjturunningman`。

该目录包含 `settings.json` 与 `routes/`。地图 HTML 只保存在内存中，由按需启动的本机服务提供，不开放文件目录；服务随客户端退出而关闭。旧版程序目录中的 `Routes/`、`user.txt` 和 `ui_settings.json` 不会自动迁移；通过导入 TXT 迁移路线即可。

## 构建与验证

需要 Rust 1.95+、Node.js 22+、pnpm 11+，以及对应平台的 Tauri 系统依赖（见 [build.md](build.md)）。

```bash
pnpm --dir desktop install --frozen-lockfile
pnpm --dir desktop tauri dev        # 开发：Vite 1420 + Tauri 窗口
pnpm --dir desktop build            # 前端 typecheck + 生产产物
cargo test --workspace --locked
cargo build --release --locked -p sjturunningman --features custom-protocol

# 后端离线检查（不启动窗口）
./target/release/sjturunningman --smoke-test target/smoke
# 真实 WebView 界面检查（启动窗口、点击承诺书、遍历四个页面后退出）
./target/release/sjturunningman --ui-smoke-test target/ui-smoke
```

> 直接 `cargo run` 时 Tauri 处于开发模式，会去连接 `http://localhost:1420`；请改用 `pnpm --dir desktop tauri dev`，或构建带 `--features custom-protocol` 的 Release 二进制。发布构建必须带该 feature，否则前端资源不会按生产模式加载。

Windows 可运行 `./build_windows.ps1`（会先构建前端），产物为 `dist/SJTURunningMan.exe`。三系统打包见 [build.md](build.md)。自动测试不会提交真实账号或运动记录；真实账号登录、二次验证与上传仍需单独验收。详见 [验证记录](desktop-validation.md) 与 [验收清单](testing.md)。

## 轻量化设计

桌面端不打包 Chromium、Qt、Python 或整套背景资源，使用操作系统自带的 WebView。前端由 Vite 构建后嵌入二进制；Roboto 与 Material Symbols 只保留实际用到的子集（约 100 KB）。路线预览默认在卡片内加载在线底图；路线管理页收起地图后使用随主题着色的本地 SVG，加载地图页面失败时也保留本地预览。调用认证与上传只发生在用户动作之后。Release 使用体积优化、LTO 和符号裁剪。体积和启动耗时应以各系统的实际 Release 构建测量，不将 Debug 产物或旧版本下载包视为同条件基准。

轨迹采样保留原始拐点，避免跨弯道导致距离变短。当前实现保留旧桌面端的坐标校准与 payload 字段，并重写了路线采样器；单次距离统一为 1.20–5.00 km，已取消固定 200 m 距离补偿；不是与 Python 逐位相同的随机轨迹。手机端未修改。

整批任务正常结束、至少成功上传一条且没有失败时，窗口底部两侧会喷出一次鲜艳彩色纸屑，混入少量 🎉、🏃、🏅、⭐、🦄、💩 Emoji，约 3 秒后自动消失，不影响操作。手动停止、报错、部分失败、没有可上传日期及离线预览均不触发；系统开启“减少动态效果”时跳过动画，仍通过临时通知显示任务结果。旧版系统 WebView 不支持 Emoji 图像渲染时保留彩纸效果。

工作台底栏仅在任务运行期间显示任务状态；结束后收起状态行，保留学期进度和开始任务按钮，结果通过临时通知展示。
